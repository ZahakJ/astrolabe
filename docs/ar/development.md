# التطوير

*تشغيل فيلم من المصدر، وسكربتات البوابات، وأدوات لقطات الشاشة، وكيف تساهم بتغيير.*

---

## وضع التطوير

```sh
npm run dev
```

يشغّل خادم الواجهة البرمجية وVite بإعادة التحميل الساخن جنبًا إلى جنب.

| المنفذ | ما هو | متى |
| ---- | ---- | ---- |
| 6801 | خادم Hono (الواجهة البرمجية + العميل المبني) | `npm start` / دائمًا |
| 5801 | خادم تطوير Vite (يوكّل `/api` ← 6801) | `npm run dev` فقط |

`PORT` يغلب منفذ الخادم.

## السكربتات

| السكربت | ما يفعله |
| --- | --- |
| `npm run dev` | خادم الواجهة البرمجية (`--watch` الخاص بـNode) وVite جنبًا إلى جنب |
| `npm run build` | يبني العميل في `dist/`. الخادم لا يحتاج إلى بناء؛ يشغّل Node ملفات TypeScript مباشرة |
| `npm start` | يبني ثم يقدّم |
| `npm run serve` | يقدّم بلا إعادة بناء |
| `npm run hash-password` | يطلب (بلا صدى، أو من stdin) ويطبع تجزئة argon2id لـ`ADMIN_PASSWORD_HASH` |
| `npm run typecheck` | `tsc --noEmit`: بوابة TypeScript الصارمة |

## البوابات

كل منها يخرج بقيمة غير صفرية عند الفشل. بوابات المنطق الخالص لا تحتاج شيئًا؛ وبوابات المتصفح تحتاج نسخة تعمل مع `npm i -D playwright` وإما `npx playwright install chromium` أو متصفح نظام عبر `CHROMIUM=/usr/bin/chromium`. والتي تسجّل الدخول تأخذ `VELLUM_PASSWORD` (الوضع المحلي المفتوح لا يحتاج كلمة مرور).

### `npm run check-i18n`: القاموس

يفشل إن كان أي مفتاح `t()` ناقصًا أو غير مترجم أو ميتًا، أو إن اختلف الجانبان الإنجليزي والعربي لمدخل حول `{عناصره النائبة}`، ويفشل أيضًا على نص إنجليزي مضمّن في JSX *و*في بناة DOM الأمرية. يُعدّ "الميت" من مواضع الاستدعاء فقط: ملف القاموس مستثنى من مسح الاستخدام، لأن مفتاحًا قيمته الإنجليزية هي اسمه (`read: { en: "read" }`) يطابق داخل تعريفه لولا ذلك ويبلّغ عن نفسه مستخدمًا.

### `npm run check-contrast`: بوابة إمكانية الوصول

يُلزم كل سمة من الإحدى والعشرين في `client/styles/tokens.css` بـWCAG على رموز النص الأربعة: نص الجسد والنص الثانوي ضد الأرضيات الثلاث كلها (`--bg` والأسطح المرفوعة وأرضية التحويم التي تجلس عليها حبوب الوسوم)، والتمييز ضد الصفحة، و`--text-faint` عند عتبة 3:1 لغير النص على الأرضيتين المرخَّص له بالرسم عليهما. يُقرأ زوج التمييز نصًا مرتين (روابط الويكي وحبوب الوسوم في النثر، وحبّة الوضع المضاءة، وهي اللونان نفسهما مبدَّلين). شغّله بعد مسّ رموز السمات.

تعيش الصيغ والعتبات في `shared/contrast.ts`، الذي يستورده [منشئ السمات المخصصة](theming.md#make-your-own) أيضًا؛ تنفيذ واحد، وإلا بارك منشئ يومًا سمة ترفضها البوابة.

يُلزم أيضًا **لوحات ألوان النص** (`shared/textColors.ts` و`client/styles/textcolor.css`)، الموجودة على مستويين لسبب حسابي: ضد `#050508` في `void` يحتاج اللون إلى إضاءة نسبية ≥ 0.186 وضد `#ffffff` في `solar` يحتاج إلى ≤ 0.183، فـ**لا لون واحد يجتاز AA على كل سمة**. فيحمل المستوى المراعي للسمة (`var(--vc-*)`، الافتراضي) قيمة واحدة لكل *مجموعة* سمات ويُلزم بـ4.5:1 ضد كل أرضية في مجموعته؛ ويحمل المستوى ثابت الحبر قيمة hex واحدة لكلها ويُلزم بـ3:1، أرضية WCAG 1.4.11 لغير النص، وهي أقصى ما يستطيع لون ثابت الوعد به. تطبع البوابة الاثنين وتفحص قيم ورقة الأنماط ضد الوحدة.

### `npm run check-sections`: بوابة جراحة الأقسام

بلا متصفح ولا خادم. سحب عنوان في المخطط يعيد كتابة الملاحظة، تغادر كتلة أسطر مكانًا وتصل إلى آخر مع إعادة تسوية مستوى الشجرة الفرعية المنقولة، وهي أشد العمليات تدميرًا في المنتج مما لا يُسمى "حذفًا": تعمل على إيماءة بلا مفتاح، وعلى بعد انزلاق 4px بالصدفة، والقارئ ينظر إلى مخطط من أربعين صفًا لا إلى الـ1,200 سطر التي يعيد ترتيبها، فالفقرة الواحدة المسقطة ستكون غير مرئية حتى اليوم الذي تلزم فيه.

تولّد البوابة آلاف المستندات من الأشكال التي تكسر التنفيذات الساذجة، مقدمة YAML وسياجات كود تحوي أجسادها أسطر `### ` وعناوين تتخطى مستويات وأقسامًا فارغة وقسمًا في آخر الملف وCRLF وبلا سطر جديد ختامي، وتؤكد أن إعادة الترتيب **تبديل**: يجوز لها تغيير ترتيب أسطر الملاحظة وعمق عناوين الشجرة الفرعية المنقولة نفسها، ويجوز لها إضافة سطر فارغ عند درز؛ ولا يجوز لها أبدًا فقد سطر ولا تكرار سطر. تؤكد أيضًا أن القسم لا يمكن إسقاطه داخل نفسه، وأن النقل بمسافة صفر لا يفعل شيئًا، وأن نصفَي الاستخراج يغطيان الأصل بالضبط. `SEED=…` يعيد تشغيل فشل، و`ROUNDS=…` يضبط حجم العينة.

### `npm run check-caret`: بوابة النقر إلى المؤشر

تستبدل المعاينة الحية بمصدر ماركداون صناديق معروضة بعرض مختلف *و*طول مختلف، ثمانية عشر حرفًا من `$7.7\ \text{km/s}$` تقف تحت سبعة حروف من KaTeX، فأي تعيين من المؤشر إلى المستند يفكر بالهندسة بدل DOM ينحرف بذلك الفرق بالضبط.

تكتب ملاحظتها الخاصة (رياضيات سطرية وكود سطري وروابط ويكي ووسوم وتظليل وصورة، بالإنجليزية والعربية، على أسطر طويلة بما يكفي لتلتف مرات)، وتقود فأرة حقيقية فوقها، نقرة مفردة ومزدوجة وثلاثية وسحبًا ونقرة مع Shift وتحديد الكل، وتشغّل المصفوفة كلها مرة في كل اتجاه قشرة، وتقرأ ما سينسخه القارئ فعلًا (`window.getSelection()`)، مطالبة كل حرف منقور بأن يأخذ المؤشر **في حدود حرف واحد**. قبل الإصلاح بلّغت عن أخطاء حتى **82 حرفًا**؛ وبعده صفر.

توجد لأن ذلك السؤال الواحد انكسر أربع طرق منفصلة هنا (موضع النقر ومعاينات التحويم والتنقل بالنقر مع المعدّل وتحديد النص) والسبب المشترك دائمًا بكسل لا تراه خريطة ارتفاعات المحرر: **لا شيء داخل `.cm-content` يجوز أن يحمل هامش CSS عموديًا.** يقيس CodeMirror كل سطر وعنصر كتلي بصندوق حدوده، فتُحسب الحشوة والحدود ولا تُحسب الهوامش؛ ضع الهواء على حشوة غلاف، أو في حد شفاف مع `background-clip: padding-box`، لا في هامش أبدًا. تعيد لغة النسخة وتحذف تركيبها كيفما انتهى التشغيل.

### `npm run check-layouts`: بوابة تخطيط لوحة المفاتيح

`KeyboardEvent.key` هو ما أنتجه *التخطيط*. كانت القشرة تقارنه بحروف لاتينية، فعلى لوحة مفاتيح عربية، حيث يبلّغ المفتاح المعلَّم `P` عن `ح`، كان كل اختصار عام في المنتج ميتًا، في تطبيق يشحن ترجمة عربية كاملة ويعكس واجهته كلها لها. كان غير مرئي لكل اختبار عندنا، لأن كل اختبار كان يكتب حروفًا لاتينية.

فهذه لا تفعل. تقود التطبيق الحقيقي عبر بروتوكول DevTools (`Input.dispatchKeyEvent`، الطريقة الوحيدة لضبط `key` و`code` و`keyCode` على استقلال؛ لوحة مفاتيح Playwright نفسها ترسل دائمًا `key` الأمريكي لـ`code`) بضغطات المفاتيح التي ترسلها فعلًا العربية 101 وЙЦУКЕН واليونانية والعبرية وAZERTY وDvorak وQWERTY الأمريكية، وتؤكد أن اللوحة والمخطط وورقة الاختصارات والصفاء وعرض القراءة والبحث ومبدّلات اللوحات والغامق والشطب كلها ما زالت تُطلق، بما فيه `Ctrl/Cmd K` في قشرة المدونة غير المسجَّلة، وهو الارتباط الوحيد للقارئ المجهول. **72 فحصًا؛ 46 منها نجحت قبل الإصلاح.**

نصفها الثاني هو الذي يمنع الإصلاح من الإفراط في التصحيح: على Dvorak المفتاح الذي يكتب `b` هو `KeyN` الفيزيائي، فـ`Ctrl Alt` على `KeyB` الفيزيائي، الذي يكتب `x` هناك، يجب ألا يفعل **شيئًا**. التخطيط أولًا، والموضع بديلًا فقط. `tests/shortcuts.test.ts` يشغّل المصفوفة نفسها على المحلّل بلا متصفح البتة، ويحمل الحالات التي لا يستطيع متصفح تسليمها (يسطّح Chromium لام ألف العربية ذات نقطتَي الكود إلى `key` فارغ). والارتباط المضاف إلى ورقة الاختصارات وليس إلى ذلك الملف ارتباط غير مختبر على كل لوحة مفاتيح غير لاتينية على وجه الأرض.

`node scripts/shoot-layouts.mjs` هي الصورة المرافقة: ورقة `Ctrl/Cmd /` مع خريطة التخطيط مقلَّدة بالعربية والروسية، وهي طريقة مراجعة أغطية المفاتيح المشروحة.

### `npm run check-keymap`: دفتر الارتباطات

الاختصار المتصادم أهدأ علّة يمكن أن يحملها هذا المنتج. معالج يجيب على المفتاح، والآخر لا يرى الحدث أبدًا، ولا يعرف أي منهما بوجود الآخر، فيظهر بعد أسابيع بوصفه "Ctrl+B لا يفعل شيئًا"، على منصة واحدة، من قارئ واحد، بلا شيء يُبحث عنه، لأن لا شيء خاطئ في أي من الارتباطين. الخطأ أن هناك اثنين.

فالارتباط يوجد في مكان واحد: جدول `GROUPS` في `client/components/ShortcutsHelp.tsx`، الجدول نفسه الذي يطبعه `Ctrl/Cmd /`. تحلله هذه البوابة من نص المصدر (لا تستورده أبدًا؛ تحمل الصفوف إغلاقات React والمخزن، وبوابة تحتاج متصفحًا بوابة لا يشغّلها أحد)، وتحوّل `keys` كل صف إلى وتر مقنَّن، وتفشل حين يحلّ صفان إلى المفتاح والمعدّلات والنطاق نفسها. النطاق هو القشرة (`app` / `blog`) ووقت التشغيل (متصفح / سطح مكتب)، وعمدًا **ليس** `admin`: ترى جلسة المشرف صفوف الزائر زائد صفوفها، فـ`admin` لا يفصل ارتباطين أبدًا؛ يسمّي القارئ الذي يبلغه التصادم أولًا.

تداخل واحد حقيقي، محاجَج ومعلَن: `Ctrl/Cmd Shift Z` هو الصفاء *و*ارتباط الإعادة الوحيد لـCodeMirror على macOS، و`client/App.tsx` يحسم بالمؤشر. إعلان واحد يكلف فقرة في `RESOLVED` (`client/keymap.ts`) تقول أين يُحسم، والإعلان الذي يكفّ عن التصادم يُفشل البناء أيضًا؛ الاستثناء الميت ادعاء يصدّقه القارئ التالي.

النصف الثاني هو `docs/keymap.md`، وهو عرض للدفتر لا نسخة ثانية منه: تقارن البوابة الأوتار في الجداول بين `<!-- keymap:begin -->` و`<!-- keymap:end -->` ضد `GROUPS`، في الاتجاهين. الأسطح التي لا تحمل ضغطة مفتاح، نقرة أو قائمة الشرطة المائلة أو سحب في المخطط، تعيش تحت علامة النهاية حيث تتركها البوابة وشأنها. `tests/keymap.test.ts` يشغّل الكود نفسه بلا ملفات تُكتب.

### `npm run check-excerpt`: بوابة الوسم في النثر

قاعدة `DESIGN.md` الصارمة أن المقتطف خارج المحرر إما ينزع ماركداون أو يعرضه؛ إزالة `#` وترك الكلمة واقفة في الجملة ليست أيًّا منهما، وشُحنت: تدوينة تنتهي بـ"…it buys the reader a breath. #design #typography" طُبعت على الواجهة "…it buys the reader a breath. design typography". الأسطح الثلاثة التي تتدفق عبر نازع واحد (`stripInlineMd`) تُمشى كلها من تركيب واحد **ينتهي** جسده بسطر وسوم: مقتطف التدوينة (`/api/posts`: بطاقات المدونة وRSS و`og:description`)، ومقتطف البحث (`/api/search`)، وسطر سياق الرابط الراجع (`/api/backlinks`). تفحص أيضًا الاتجاه الآخر، أن الجملة المنزوعة تنجو وأن الوسوم ما زالت تظهر حيث تنتمي الوسوم (`post.tags`، وفهرس البحث ما زال يطابقها)، فالنازع الذي ينجح بحذف كل شيء يفشل أيضًا. بلا متصفح؛ وتحذف تركيباتها كيفما انتهى التشغيل.

### `npm run check-design`: حدّ الخطأ

بوابة الوعد الوحيد في [محرك التصميم](designer.md) الذي لا يمكن مراجعته بالقراءة. تكسر موقعًا مصمَّمًا ثلاث طرق عمدًا (ملف `designs.json` فاسد، وقسم يشير إلى ملاحظة غير موجودة، ومُعرِّض قسم مرقَّع ليرمي ومعاد بناؤه)، ولكل منها تقيس ما يأخذه الزائر (المدونة المدمجة، وصفحة بنص حقيقي، ولا شيء يفلت من الحد) ضد ما يأخذه المالك (الصفحة المصمَّمة، والقسم الفاشل مسمًّى، وعنصر الرجوع موجود). تدور أيضًا الجاهز ⇄ المصمَّم وتؤكد أن التصميم يعود متطابقًا بايتًا بايت. كل ما مسّته يُعاد في طريق الخروج، حتى عند الفشل: `PORT=6801 VELLUM_PASSWORD=… npm run check-design`.

### `npm run check-board`: لوحة أقسام المصمم

ثلاث طرق لتحريك صف (زرّا ↑/↓، وسحب بالمؤشر، ورفع بلوحة المفاتيح `Space`/الأسهم/`Space`)، ومعاينة الإسقاط قبل التثبيت، و`Esc` للطبقة الأعمق، وعدّ شريط الحفظ، ودورة `Ctrl/Cmd S` عبر المخزن.

### `npm run check-preview`: معاينة المصمم الحية

أنها إطار iframe حقيقي تحت `frame-src 'none'`، وأن الأنماط والسمة تصلها (بما فيه تبديل سمة حي)، وأنها تُخطَّط بعرض أجهزة 390 / لوحي / 1440.

### `npm run check-print`: الصفحة المطبوعة

`PORT=6801 npm run check-print`. السطح الوحيد الذي لا ينظر إليه أحد أثناء العمل: قواعد `@media print` غير مرئية لكل أدوات لقطات الشاشة أعلاه، لأن المتصفح لا يطبّقها إلا حين يفتح إنسان حوارًا. فتقود هذه التطبيق تحت `emulateMedia("print")` وتؤكد أن مضيف الطباعة هو الشيء الوحيد على الورق (وأنه `display: none` على الشاشة، فلا يومض أبدًا)، وأن لوحة الورق تغلب من سمة داكنة، وأن التنبيه المطوي يطبع جسده، وأن العناوين تبقى `h1`–`h6` حقيقية بمعرّفات وأن المراسي الداخلية تحتفظ بـ`href` أجزاء، وهما الشيئان اللذان يبني منهما Chrome مخطط إشارات PDF وتعليقات روابطه، وأن الملاحظة العربية تُطبع صفحة من اليمين إلى اليسار من نسخة إنجليزية. تكتب ملاحظتَي تركيب عبر الواجهة البرمجية وتحذفهما في طريق الخروج. انظر [الطباعة وPDF](printing.md).

### `npm run check-presets`: كتالوج الإعدادات المسبقة

معرّفات مختصرة فريدة، واسم وتعريف ثنائيا اللغة بعربية حقيقية، وعائلة معروفة، وإعداد واحد على الأقل لكل عائلة، ولا إعداد يسمّي ملاحظة في خزانة أحد. تشغّل `assertCatalog` المشترك بدل إعادة تنفيذه.

## أدوات لقطات الشاشة

غير موصولة بـ`package.json`؛ تُشغَّل باليد للمراجعة البصرية. كلها تأخذ `CHROMIUM`، ومعظمها يأخذ `THEME=parchment` و`LANGSET=ar` لفحص سمة أو الانعكاس من اليمين إلى اليسار.

| الأداة | تلتقط |
| --- | --- |
| `node scripts/shoot.mjs <url> <outdir>` | المحرر والمخطط واللوحة في السمتين |
| `node scripts/shoot-settings.mjs <url> <password> <outdir>` | كل قسم إعدادات عبر السكة، مع طباعة هندسة تمرير اللوحة وأحجام خط النموذج |
| `node scripts/shoot-sync.mjs <url> <password> <outdir>` | قسم النسخ الاحتياطي والمزامنة إضافة إلى لوحة تفاصيل شارة الحالة |
| `node scripts/shoot-themes.mjs` | كل سمة (`ONLY=` يضيّقها) |
| `node scripts/shoot-rtl.mjs` | الانعكاس العربي، ويؤكد ترتيب الحروف في شرائح الوسوم |
| `node scripts/shoot-tex.mjs` | ملاحظات `.tex`، بست تأكيدات |
| `node scripts/shoot-templates.mjs` | منتقي القوالب، بتأكيدات |
| `node scripts/shoot-hover.mjs` | معاينات التحويم، بتأكيدات |
| `node scripts/shoot-controls.mjs` | مجموعة عناصر التحكم المرسومة باليد (`W`/`H` يضبطان نافذة العرض) |
| `node scripts/shoot-fontupload.mjs` | رافع الخطوط |

## المساهمة بتغيير

1. **اقرأ `DESIGN.md` و`CONTRACTS.md` أولًا.** يحمل `DESIGN.md` القواعد التي يُحاكم بها التغيير؛ ويحمل `CONTRACTS.md` الثوابت التي التزم بها الكود أصلًا. معظم تعليقات المراجعة هنا أحد هذين المستندين مقتبسًا.
2. **شغّل `npm run typecheck`.** البناء صارم والخادم بلا خطوة ترجمة تلتقط الأشياء لاحقًا.
3. **شغّل البوابات التي يمسّها تغييرك**: رموز السمات تعني `check-contrast`، وأي نص مرئي للمستخدم يعني `check-i18n`، والمخطط أو كود إعادة كتابة الملاحظات يعني `check-sections`، والمحرر يعني `check-caret`، والمصمم يعني `check-board` / `check-preview` / `check-design`، و**كل ما يقرأ ضغطة مفتاح يعني `check-keymap` و`check-layouts` إضافة إلى `tests/shortcuts.test.ts`**: هل الارتباط فريد، وهل تستطيع لوحة مفاتيح غير لاتينية بلوغه.
4. **اللغتان، الاتجاهان.** كل نص يأتي من `client/i18n.ts`، وكل تخطيط مبني على خصائص CSS المنطقية. التغيير الذي لا يُقرأ بصحة إلا من اليسار إلى اليمين غير منتهٍ؛ `LANGSET=ar` على أي أداة لقطات أرخص طريقة لرؤيته.
5. **قل لماذا في الكود.** تعليقات هذه الشيفرة تشرح القرار لا الآلية. والرقعة التي تغيّر قاعدة يجب أن تنقل الفقرة التي ذكرتها.
